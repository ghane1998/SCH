# سیستم جامع مدیریت هوشمند مدرسه (Comprehensive School Management System)

این سند جامع (Comprehensive Documentation) به عنوان یک راهنمای کامل برای درک معماری، راه‌اندازی و توسعه این نرم‌افزار تهیه شده است. این مستند به شکلی تدوین شده که توسعه‌دهندگان و دستیارهای هوش مصنوعی (AI Assistants) بتوانند با مطالعه آن دید کاملی از نحوه کارکرد، جریان داده‌ها (Data Flow)، مدل ذخیره‌سازی و ترفندهای (Nuances) پیاده‌سازی به دست آورند.

## ۱. معرفی کلی نرم‌افزار

این نرم‌افزار یک پلتفرم یکپارچه مبتنی بر وب (Full-Stack Web Application) برای مدیریت پایگاه داده محور یک مدرسه است. طراحی این سیستم به گونه‌ای است که نیازهای تمام ذی‌نفعان مدرسه (مدیر اجرایی/آموزشی، معلمان، و دانش‌آموزان/اولیا) را پوشش می‌دهد.

### ویژگی‌های کلیدی:
- **معماری Full-Stack:** استفاده از پنل و سرور یکپارچه با Node.js و Express همراه با React.
- **ذخیره‌سازی هوشمند (Hybrid Database Approach):** پشتیبانی همزمان از دیتابیس سبک (SQLite) برای توسعه محلی و تست سریع، و دیتابیس قدرتمند (PostgreSQL) برای استقرار روی سرورهای عملیاتی (Production).
- **تزریق خودکار داده (Auto-Seeding):** در اولین اجرای برنامه در صورتی که دیتابیس خالی باشد، داده‌های پیش‌فرض آموزشی شامل معلم، دانش‌آموز، کلاس و ... ایجاد می‌شود.

## ۲. تکنولوژی‌ها و معماری (Tech Stack & Architecture)

- **Frontend:** 
  - **Framework/Libraries:** React 19, TypeScript, `react-router-dom` (برای مسیریابی کلاینت به صورت HashRouter).
  - **Styling:** Tailwind CSS (طراحی ریسپانسیو و Mobile-first).
  - **Icons:** `lucide-react`
  - **Build Tool:** Vite
- **Backend:**
  - **Runtime & Framework:** Node.js, Express.js
  - **Language:** TypeScript (توسط `tsx` به صورت زنده برای توسعه و کامپایل شده برای پروداکشن).
- **Database Layer:**
  - **SQLite:** از طریق `better-sqlite3`. (فایل محلی `school.db`).
  - **PostgreSQL:** از طریق `pg`. (متصل از طریق Connection String).

### مدل اجرایی سرور (Vite Middleware in Express):
سرور این پروژه (در فایل `server.ts`) از یک الگوی بسیار مدرن پیروی می‌کند:
- در **محیط توسعه (Development)**: Vite به صورت Middleware درون Express سوار می‌شود (`middlewareMode: true`). این یعنی API ها و Web interface همزمان روی یک پورت (۳۰۰۰) پاسخگو هستند. تمام درخواست‌هایی که با `/api/` شروع شوند به Endpoint های اکسپرس می‌روند و مابقی توسط Vite (برای React) پردازش می‌شوند.
- در **محیط عملیاتی (Production)**: بعد از گرفتن خروجی (`npm run build`)، اکسپرس فولدر `dist` را به عنوان محتوای استاتیک (Static Files) سرور می‌کند و همچنان روی پورت مستقل خودش API ها را هندل می‌کند.

## ۳. معرفی ماژول‌ها و سطوح دسترسی (Roles & Modules)

### Role: Admin (مدیریت)
مدیریت کامل سیستم بر عهده ادمین است. او به منوها و قابلیت‌های زیر دسترسی دارد:
- **داشبورد آماری:** نمای کلی از تعداد دانش‌آموزان، درآمدها، رویدادها.
- **ثبت‌نام و کاربران:** مدیریت معلمان و دانش‌آموزان، تخصیص آنها به کلاس‌ها. اطلاعات بسیار دقیق از دانش‌آموز گرفته می‌شود (شامل وضعیت سلامت، اطلاعات ولی، داده‌های پزشکی، وضعیت چپ‌دستی و...).
- **امور مالی:** صدور صورت‌حساب گروهی یا فردی (Bills) و ثبت و تایید پرداخت‌ها (Payments) با روش‌های مختلف (نقد، چک، فیش).
- **مدیریت دارایی‌ها (Assets):** ثبت اموال مدرسه (با بارکد) و تخصیص موقت آنها (نظیر تبلت یا کتابخانه) به دانش‌آموزان.
- **گیمیفیکیشن و نشان‌ها (Badges):** تعریف مدال‌های سیستم جهت تشویق و اهدای آن‌ها به دانش‌آموزان.
- **مدیریت اعلانات (Notifications):** 
  - ارسال اعلان فوری با پشتیبانی از تصویر ضمیمه.
  - اعلانات زمان‌بندی شده (Scheduled) نظیر تبریک تولد؛ که با ترکیب قالب متنی (مثل `{firstName} تولدت مبارک`) به صورت داینامیک برای هر کاربر ساخته می‌شود.
- **فعالیت‌های فوق برنامه و شورای دانش‌آموزی (Responsibilities):** انتصاب دانش‌آموزان به عنوان نماینده، شهردار مدرسه و... .

### Role: Teacher (معلم)
معلم تنها اطلاعات کلاس‌ها و دانش‌آموزانی که به او منتسب شده را می‌بیند.
- **کلاس‌های من:** لیست کلاس‌ها و دانش‌آموزان.
- **نمرات و ارزیابی:** ثبت نمرات توصیفی یا کمی برای دروس محول شده.
- **حضور و غیاب:** پایش غیبت یا تاخیر، یادداشت دلیل غیبت و اطلاع به اولیا.
- **سوابق انضباطی و پرورشی:** معرفی موارد مثبت یا منفی انضباطی (Disciplinary Incidents) و وقایع‌نگاری رفتاری (Anecdotal Records).
- **ارتباط با اولیا:** ثبت گزارش از جلسات برگزار شده با اولیای دانش‌آموزان (Parent Meetings).
- **انجمن اولیا مربیان (PTA):** مدیریت برگزاری جلسات کلیدی اولیا.

### Role: Student (دانش‌آموز/ولی)
با لاگین به این نقش دیدگاه یک دانش‌آموز نمایش داده می‌شود.
- **داشبورد من:** مشاهده نمرات، رویدادهای پیش‌رو در تقویم، وضعیت چکیده مالی، و مدال‌های کسب شده.
- **صندوق پیام:** دریافت اعلانات عمومی، کلاسی و تولد.
- **اطلاعات کلاس و برنامه تقویمی.**
- **مالی:** مشاهده صورت‌حساب‌های پرداخت شده و پرداخت‌نشده.

## ۴. مدل پایگاه داده و ذخیره‌سازی داده‌ها (Data Model & Schema)

### مکانیزم هوشمند دوگانه (SQLite vs Postgres)
این یکی از مهم‌ترین بخش‌های فنی پروژه است. در فایل `database.ts` موتور دیتابیس بر اساس وجود متغیر محیطی `DATABASE_URL` انتخاب می‌شود.
- **انطباق نوع داده (Data Type Serialization):**
  از آنجا که بسیاری از موجودیت‌های ما داده‌های ساختاریافته هستند (مانند لیست مقاصد یک پیام، و یا اطلاعات سلامت یک دانش‌آموز)، در برنامه‌نویسی باید به صورت JSON ذخیره شوند.
  - در **PostgreSQL** ما از نوع داده `JSONB` استفاده کردیم. از این رو در `server.ts` داده‌ها بدون تغییر (به صورت آبجکت) تحویل متد کوئری می‌شوند. پایگاه داده مستقیما آن ها را پردازش میکند.
  - در **SQLite** نوع داده JSON بومی نداریم. لذا، قبل از ثبت در دیتابیس این فیلدها توسط `JSON.stringify` به نوع متن تبدیل شده، و هنگام خواندن (`SELECT`) توسط `JSON.parse` دوباره به آبجکت تبدیل می‌شوند. به همین شکل مقادیر بولین در SQLite به `INTEGER` (0 و 1) و در Postgres مستقیما `BOOLEAN` ذخیره می‌شوند. این کار در لایه روت‌های `server.ts` به زیبایی مدیریت شده است.

### جداول اصلی (Master Tables)
1. `admins`, `teachers`, `students`: موجودیت‌های انسانی.
2. `classes`: رابطه بین معلم و درس، که معمولا آی‌دی معلم را نگه می‌دارد.
3. `grades`: نمرات (کمی و کیفی).
4. `attendance`: وضعیت حضور.
5. `discipline`, `anecdotal_records`: ثبت داده‌های رفتاری و انضباطی.
6. `exams`: برنامه امتحانی.
7. `bills` و `payments`: زیرساخت مالی. رکوردهای مالی در `bills` ثبت شده و پرداخت‌ها در `payments` با رفرنس به آی‌دی صورت‌حساب ذخیره می‌گردند.
8. `events`: رویدادهای همایشی، اردوها و...
9. `responsibilities` , `responsibility_assignments`: مسئولیت‌های دانش‌آموزی (شورای مدرسه).
10. `parent_meetings`, `pta_meetings`, `pta_attendance`: نشست‌های والدین.
11. `assets`, `asset_assignments`: اموال و مدیریت تخصیص آن‌ها (شامل بارکد).
12. `badges`, `awarded_badges`: تعریف و امتیازدهی گیمیفیکیشن.
13. `notifications`, `scheduled_notifications`: باکس پیام‌ها.
14. `settings`: تنظیمات سراسری پلتفرم.

## ۵. راهنمای نصب و راه‌اندازی (Installation & Deployment)

برای راه‌اندازی این سیستم، نیازمندی‌های پایه شامل `Node.js (>= 18)` و ابزارهای پکیج منیجر نظیر `npm` است.

### ۱. نصب وابستگی‌ها
دستور زیر را در مسیر root پروژه اجرا کنید:
```bash
npm install
```

### ۲. تنظیمات متغیرهای محیطی (Environment Variables)
شما می‌توانید فایل `.env.example` را به `.env` تغییر نام دهید. پارامترهای زیر پشتیبانی می‌شوند:
```env
# اتصال به موتور پایگاه داده حرفه‌ای (در صورت خالی بودن، برنامه فایل محلی SQLite را می‌سازد)
DATABASE_URL=postgres://username:password@localhost:5432/school_db

# در صورت استفاده از قابلیت‌های هوش مصنوعی
GEMINI_API_KEY=your_key
```

### ۳. راه‌اندازی برای توسعه (Development)
جهت توسعه و اعمال تغییرات به صورت زنده، از دستور زیر استفاده کنید:
```bash
npm run dev
```
- سیستم ابتدا سعی می‌کند دیتابیس را کانکت کند.
- در صورتی که جداول وجود نداشته باشند (اولین اجرا)، خود به خود `CREATE TABLE` ها اجرا می‌شوند.
- سپس توابع `bulkInsert` فراخوانی شده تا داده‌های نمونه و نمایشی (Mock Data) که در فایل `data.ts` تعریف شده‌اند درون دیتابیس تزریق (Seed) شوند (تولید داده‌های فیک برای پاپولیت کردن نرم‌افزار).
- سرور روی پورت `3000` بالا آمده و سرور Vite نیز با آن Integrate می‌شود. 
- آدرس دسترسی: `http://localhost:3000`
- شما با استفاده از لیست کاربرانی که در صفحه لاگین پیشنهاد می‌شود (نظیر admin1, teacher1, ...)، با پسورد سراسری دمو `password123` می‌توانید وارد سیستم شوید.

### ۴. ساخت و استقرار عملیاتی (Production Deployment)
ابتدا باید کدها را برای قرارگیری روی سرور Build و Minify کنیم:
```bash
npm run build
```
سپس سرور Node را اجرا می‌کنیم (که به جای Vite، فایل‌های تولید شده را اسکریپت می‌کند):
```bash
npm start
```
*نکته: در استقرار کانتینری (مانند Cloud Run) نیازی به نصب سرورهای وب جانبی نیست، پورت ۳۰۰۰ به صورت پیش‌فرض باز خواهد شد.*

## ۶. ارتباط با هوش مصنوعی و توسعه ثانویه (Hints for AI Assistance)

در صورتی که قصد دارید این سورس را برای اضافه کردن ویژگی جدیدی به یک دستیار هوش مصنوعی بدهید، نکات زیر را در پرامپت خود قید کنید:
1. **Model Awareness:** از هوش مصنوعی بخواهید متوجه نوع دیتابیس (گسستگی رفتاری بین SQLite و Postgres در هندل کردن مقادیر JSON و BOOLEAN) باشد و تغییرات دیتابیس در فایل `database.ts` و تغییرات CRUD را در API های `server.ts` به دقت انجام دهد. (از دستور `isPostgres` برای ایجاد تمایز استفاده شده).
2. **Type System:** سیستم بر اساس تایپ‌های قوی `TypeScript` بنا شده است. قبل از اضافه کردن یا ویرایش فیلد جدید، در اولین قدم باید فایل `types.ts` آپدیت شود.
3. **Data Mocking:** از آن جهت که پروژه هنگام خالی بودن دیتابیس Auto-seed می‌شود، فیلدهای جدید جداول را باید حتما در متغیرهای پیش‌فرض داخل فایل موک `data.ts` نیز در نظر بگیرید و آن‌ها را همگام کنید تا در زمان Seed کردن به خطا برخورد نکند.
4. **State Management:** در React این پروژه از Context API استفاده نشده و دیتابیس منبع اصلی State است؛ بنابراین باید توابع Data Fetching سمت کلاینت بعد از هر تغییر آپدیت شوند.
5. **UI Component:** به هوش مصنوعی بگویید بررسی کند فرم‌ها و جدول‌ها را از پوشه `components/common/` فرخوانی کند (نظیر `Card`, `DateSelector`, `SortableHeader`) تا ظاهر نرم‌افزار بهم نریزد و از استانداردهای گرافیکی اپلیکیشن تبعیت کند.
